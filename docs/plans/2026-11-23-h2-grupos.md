# H2 · Grupos y miembros — Plan de implementación

> **Para quien ejecute:** usá `subagent-driven-development`, con un implementador y un revisor por tarea. Las líneas **B** (IOU-backend) y **F** (IOU-client) corren en paralelo; dentro de cada línea, en orden. Cada subagente lee: este plan, `docs/api-contract.md` (sección H2), `docs/spec.md` (RN-11 a RN-13, RN-15, RN-16, CB-09, CB-14), el CLAUDE.md y, en el front, `docs/design.md`. Ledger en `IOU/.superpowers/h2/progress.md`.

**Objetivo:** que un usuario cree grupos, vea los suyos, entre al detalle, lo edite si es admin y gestione miembros (agregar por email, reactivar, quitar), con todas las reglas en el back y las pantallas con sus estados de carga, vacío y error.

**Arquitectura:**
- **Back:** las **reglas viven en los services**. `grupo.service` resuelve la membresía del actor en cada operación: 404 si no es miembro activo, 403 si hace falta ser admin, 409 si el grupo está archivado. No hay middleware con reglas de negocio. Los repositorios se inyectan, y los tests usan versiones en memoria.
- **Front:** hooks de TanStack Query por recurso, con invalidación explícita después de cada mutación. El token se agrega solo en `apiRequest`.

**Spec:** `docs/spec.md`, `docs/api-contract.md` (H2), `docs/historias-usuario.md` (HU-06 a HU-11) y `docs/design.md` (secciones 5 a 7).

## Restricciones globales

- **Ramas:** `h2-grupos` en los dos repos (en el back ya existe, con el contrato).
- Sin push ni PR por parte de los subagentes. **El contrato no se cambia**: si algo no cierra, el subagente se detiene y lo reporta.
- **Errores del H2** (texto exacto del `message`):

  | Código | HTTP | `message` |
  |---|---|---|
  | `GRUPO_NO_ENCONTRADO` | 404 | "Este grupo no existe o no sos parte" |
  | `SOLO_ADMIN` | 403 | "Solo el admin del grupo puede hacer esto" |
  | `USUARIO_NO_ENCONTRADO` | 404 | "No existe un usuario con ese email" |
  | `YA_ES_MIEMBRO` | 409 | "Ya es miembro del grupo" |
  | `MIEMBRO_NO_ENCONTRADO` | 404 | "Esa persona no es miembro del grupo" |
  | `SALDO_PENDIENTE` | 409 | "No se puede quitar: tiene saldo pendiente de {monto}", con `details.saldo` |
  | `ADMIN_NO_PUEDE_SALIR` | 409 | "El admin no puede quitarse del grupo" |
  | `GRUPO_ARCHIVADO` | 409 | "El grupo está archivado: solo se puede consultar" |

- **Validación:** `nombre` con trim, de 1 a 60 caracteres ("Poné un nombre de hasta 60 caracteres"); `descripcion` con trim, hasta 200, y vacía pasa a ser `null`.
- **`miBalance`:** `"0.00"` en el H2, a través de `SaldoProvider` (Tarea B3).

## Puntos de atención (Review Focus)

1. **Un no miembro nunca se entera de que el grupo existe:** recibe 404, nunca 403, en todas las rutas `/grupos/:id/*` (B4).
2. **Un miembro dado de baja pierde el acceso:** con `activo = false` recibe 404 en el detalle, y su grupo desaparece de `GET /grupos` (B2).
3. **Email al agregar:** `"  Tomi@Mail.com "` encuentra a `tomi@mail.com`; agregarse a uno mismo responde `YA_ES_MIEMBRO` (B3).
4. **Grupo archivado:** el `PATCH` y las altas y bajas de miembros responden 409 aunque las haga el admin. En los tests se fuerza con `archivado: true` en el repo en memoria (B2, B3).
5. **Caché del front:** después de crear un grupo, de editarlo o de agregar o quitar un miembro, la lista y el detalle se ven actualizados sin recargar (F2 a F4).

## Línea B · IOU-backend

### B1 · Modelos `Grupo` y `MiembroGrupo`

**Archivos:** `prisma/schema.prisma`, `prisma/migrations/…_grupos/`

```prisma
enum Rol { ADMIN MIEMBRO }

model Grupo {
  id          String         @id @default(uuid()) @db.Uuid
  nombre      String         @db.VarChar(60)
  descripcion String?        @db.VarChar(200)
  moneda      String         @default("ARS") @db.Char(3)
  archivado   Boolean        @default(false)
  creadoPorId String         @map("creado_por") @db.Uuid
  creadoPor   Usuario        @relation("GruposCreados", fields: [creadoPorId], references: [id])
  createdAt   DateTime       @default(now()) @map("created_at") @db.Timestamptz
  miembros    MiembroGrupo[]
  @@map("grupos")
}

model MiembroGrupo {
  grupoId   String   @map("grupo_id") @db.Uuid
  usuarioId String   @map("usuario_id") @db.Uuid
  rol       Rol      @default(MIEMBRO)
  activo    Boolean  @default(true)
  fechaAlta DateTime @default(now()) @map("fecha_alta") @db.Timestamptz
  grupo     Grupo    @relation(fields: [grupoId], references: [id], onDelete: Cascade)
  usuario   Usuario  @relation(fields: [usuarioId], references: [id])
  @@id([grupoId, usuarioId])
  @@index([usuarioId])
  @@map("miembros_grupo")
}
```

`Usuario` suma `gruposCreados Grupo[] @relation("GruposCreados")` y `membresias MiembroGrupo[]`.

- `domain/grupo.ts`: los tipos `Rol`, `UsuarioRef`, `Miembro`, `GrupoResumen` y `GrupoDetalle`, idénticos a los del contrato, y además:

```ts
type GrupoRow = { id: string; nombre: string; descripcion: string | null; moneda: 'ARS';
  archivado: boolean; creadoPor: UsuarioRef; createdAt: Date };
interface GrupoRepository {
  crear(d: { nombre: string; descripcion: string | null; creadoPorId: string }): Promise<GrupoRow>; // crea al creador como ADMIN en la misma transacción
  listarDeUsuario(usuarioId: string): Promise<(GrupoRow & { miembrosActivos: UsuarioRef[] })[]>;   // solo grupos donde está activo
  buscar(grupoId: string): Promise<GrupoRow | null>;
  membresia(grupoId: string, usuarioId: string): Promise<{ rol: Rol; activo: boolean } | null>;
  miembros(grupoId: string): Promise<Miembro[]>;
  actualizar(grupoId: string, d: { nombre?: string; descripcion?: string | null }): Promise<GrupoRow>;
}
interface SaldoProvider { saldoDe(grupoId: string, usuarioId: string): Promise<number> }  // centavos
```

- `createGrupoService({ grupos, saldos }): { listar(actorId): Promise<GrupoResumen[]>; crear(actorId, input): Promise<GrupoDetalle>; detalle(actorId, grupoId): Promise<GrupoDetalle>; editar(actorId, grupoId, input): Promise<GrupoDetalle>; contexto(actorId, grupoId): Promise<{ grupo: GrupoRow; rol: Rol }> }`. `contexto` es interno pero se exporta para B3: tira `GRUPO_NO_ENCONTRADO` si el grupo no existe o el actor no es miembro activo.
- `ceroSaldos: SaldoProvider`, que siempre devuelve 0 (se reemplaza en el H4).
