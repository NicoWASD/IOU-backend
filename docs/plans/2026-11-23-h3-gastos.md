# H3 · Gastos — Plan de implementación

> **Ejecución liviana (pedido del usuario):** sin subagentes ni revisor por tarea; lo ejecuta la sesión principal, en orden, con una sola corrida de tests, lint y build al final de cada repo. Tests solo donde hay reglas: dominio de reparto (tabla de CB-01 a CB-06), service y un test de endpoint por código de error. En el front, un test de la pestaña y uno del formulario.

**Objetivo:** cargar, listar, ver, editar y eliminar gastos con los tres modos de división (igual, montos, porcentaje), con todas las reglas en el back.

**Spec:** `docs/spec.md` (3, 4.2, 4.3, RN-01 a RN-08, RN-15, RN-17, CB-01 a CB-06, CB-12), `docs/api-contract.md` (H3) y `docs/historias-usuario.md` (HU-12 a HU-18). El contrato del H3 queda congelado como está.

## Integración y cierre (sesión principal)

1. `npm test`, `npm run lint`, `npm run build` en los dos repos (frenar el server local antes del build del back).
2. Migración aplicada en Neon `dev`; prueba manual con los dos servers locales.
3. Commits por repo; push, PR y merge **con el OK del usuario**; `prisma migrate deploy` corre en el arranque de Render.
4. `qa.md` con los CA-12.1 a CA-18.2 y validación del usuario sobre producción.
